# Critique — Build5 ChatConversationView

**Reviewer:** impeccable-swift `/critique` protocol, manual + detector
**DESIGN.md:** `evals/ChatBenchmarkV2/ChatBenchmarkV2/DESIGN.md` (iOS 26+, accent `#2563eb`, SF Pro, no drop shadows, `.safeAreaInset` compose bar)

- **impeccable-lint (SwiftSyntax CLI):** hits detected. Review below.

## Verdict

**Polish-first.**

The structural foundation is sound: correct `NavigationStack` + inline title for a drill-down chat, `.safeAreaInset(edge: .bottom)` for the compose bar, proper Reduce Motion and Reduce Transparency plumbing throughout, composite VoiceOver labels on link/PDF/photo bubbles, custom `ButtonStyle` with visible pressed states, `@ScaledMetric` on bubble min-height and chip padding, section grouping with sticky date headers, focused-state scroll anchoring, and material choices per surface. The failures are localized and mostly one-line fixes. Several P0s and P1s block a clean ship and need resolution before this is the exemplar build.

## What's working (credit where due)

The following are enumerated so a polish pass doesn't accidentally regress them:

- **DESIGN.md token references** appear inline in code comments (bubble padding, group-chat sender type, date header spec, motion curve) — every visual choice traces back to the brief, which is craft.md's explicit bar.
- `@ScaledMetric(relativeTo: .body)` on bubble `minHeight` (line 518) and `@ScaledMetric(relativeTo: .footnote)` on `chipHorizontal` (line 734) — correct Dynamic Type plumbing on custom spacing.
- Reduce Motion branch on every animation site: `scrollAnimation`, `threadAnimation`, and the reply-thread transition pick opacity-only fallbacks. Reduce Transparency branches pick opaque colors over materials everywhere materials are used. Both environment values are read at the top view (lines 45-46) and passed down explicitly — no stealth `@Environment` reads in nested structs.
- Custom `ButtonStyle`s exist for each tap context (`ChatSendButtonStyle`, `ChatGlyphButtonStyle`, `PhotoBubbleButtonStyle`) with distinct pressed treatments — matches interaction-design.md's "Pressed State Is Mandatory."
- 44×44 touch targets honored on attachment button (226), send button (253), reply chip (799) via `.frame(minWidth: 44, minHeight: 44) + .contentShape(…)`.
- Composite accessibility labels on `LinkPreviewCard` ("Link from \(sender): title. description. source"), `PhotoBubble` ("Photo from \(sender)"), `PDFBubble` ("PDF from \(sender), \(filename), \(size)") — the pattern F19 needs extended to the text bubble.
- `.continuous` corner style everywhere rounded rectangles appear — no default circular corners.
- `.monospacedDigit()` on date header and timestamps — typography.md's numeric rule honored.
- `.scrollDismissesKeyboard(.interactively)` — iMessage-grade keyboard UX.
- Materials chosen per surface role — `.bar` for compose bar, `.thinMaterial` for sticky date header, `.regularMaterial` for received bubbles and PDF row, `.ultraThinMaterial` for link preview and photo placeholder, `.thinMaterial` for reply chip. Each surface is one material; the hierarchy across surfaces is defensible.
- No drop shadows. Material carries separation, matching DESIGN.md's "Elevation: no drop shadows."
- Previews cover primary, compose-focused, Dark, and Dynamic Type XL — craft.md's state-preview bar is met.
