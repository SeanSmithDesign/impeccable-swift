# Critique — Build4 ChatConversationView

**File:** `evals/ChatBenchmarkV2/ChatBenchmarkV2/Build4_FullSetup/ChatConversationView.swift`
**Reviewer:** impeccable-swift `/critique` protocol, manual + detector
**DESIGN.md:** `evals/ChatBenchmarkV2/ChatBenchmarkV2/DESIGN.md` (iOS 26+, accent `#c97350`, SF Pro, no drop shadows, `.safeAreaInset` compose bar)

## Detector output

- **SwiftLint (`tools/.swiftlint.yml`):** 9 violations, 2 serious.
- **impeccable-lint (SwiftSyntax CLI):** 4 hits. Three of the four accessibility_label hits (lines 352, 523, 737) are false positives — the images are either `.accessibilityHidden(true)` directly or live inside `.accessibilityElement(children: .combine)` parents that the regex pass cannot see. The fourth (line 548 hardcoded font size) is valid and upheld below as F12.
- **asset-catalog-checker:** N/A — no `.xcassets` in the Build4 directory (the accent is declared inline, which is itself F1).

## Verdict

**Polish-first.**

The structural foundation is strong: correct `NavigationStack` + inline title for a drill-down chat, `.safeAreaInset(edge: .bottom)` for the compose bar (not hand-padded), proper Reduce Motion and Reduce Transparency plumbing throughout, composite VoiceOver labels on link/PDF/photo bubbles, custom `ButtonStyle` with visible pressed states, `@ScaledMetric` on bubble min-height and chip padding, section grouping with sticky date headers, focused-state scroll anchoring, and material choices that match DESIGN.md per surface. The failures are localized and mostly one-line fixes. Two P0s block a clean ship; two P1s (one accessibility, one WCAG) need resolution before this is the exemplar build.

## What's working (credit where due)

The following are enumerated so a polish pass doesn't accidentally regress them:

- **DESIGN.md token references** appear inline in code comments (bubble padding, group-chat sender type, date header spec, motion curve) — every visual choice traces back to the brief, which is craft.md's explicit bar.
- `@ScaledMetric(relativeTo: .body)` on bubble `minHeight` (line 456) and `@ScaledMetric(relativeTo: .footnote)` on `chipHorizontal` (line 643) — correct Dynamic Type plumbing on custom spacing.
- Reduce Motion branch on every animation site: `scrollAnimation`, `threadAnimation`, and the reply-thread transition pick opacity-only fallbacks. Reduce Transparency branches pick opaque colors over materials everywhere materials are used. Both environment values are read at the top view (lines 28–29) and passed down explicitly — no stealth `@Environment` reads in nested structs.
- Custom `ButtonStyle`s exist for each tap context (`ChatSendButtonStyle`, `ChatGlyphButtonStyle`, `PhotoBubbleButtonStyle`) with distinct pressed treatments — matches interaction-design.md's "Pressed State Is Mandatory."
- 44×44 touch targets honored on attachment button (194), send button (222), reply chip (708) via `.frame(minWidth: 44, minHeight: 44) + .contentShape(…)`.
- Composite accessibility labels on `LinkPreviewCard` ("Link from \(sender): title. description. source"), `PhotoBubble` ("Photo from \(sender)"), `PDFBubble` ("PDF from \(sender), \(filename), \(size)") — the pattern F19 needs extended to the text bubble.
- `.continuous` corner style everywhere rounded rectangles appear — no default circular corners.
- `.monospacedDigit()` on date header and timestamps — typography.md's numeric rule honored.
- `.scrollDismissesKeyboard(.interactively)` — iMessage-grade keyboard UX.
- Materials chosen per surface role — `.bar` for compose bar, `.thinMaterial` for sticky date header, `.regularMaterial` for received bubbles and PDF row, `.ultraThinMaterial` for link preview and photo placeholder, `.thinMaterial` for reply chip. Each surface is one material; the hierarchy across surfaces is defensible.
- No drop shadows. Material carries separation, matching DESIGN.md's "Elevation: no drop shadows."
- Previews cover primary, compose-focused, Dark, and Dynamic Type XL — craft.md's state-preview bar is met.
