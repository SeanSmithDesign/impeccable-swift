# impeccable-swift 3.0 Upgrade Plan

Internal scoping doc. Not shipped (`docs/` is gitignored).

**Upstream base:** `pbakaus/impeccable@f5e82162` (3.0 HEAD, merged 2026-04-24 via PR #109).
**Port branch:** `claude/impeccable-3-0-upgrade-4MsLs`.
**Target release:** `impeccable-swift v0.2.0`.

## Locked decisions

Five calls made with the user on 2026-04-24. Sub-agents in Phase 2 work from this brief.

### 1. Live Mode — stub only

Upstream's browser-based element picker + HMR variant cycling has no faithful Apple-native analog (no DOM introspection, no HMR in compile-and-run SwiftUI). Ship `reference/live.md` that:

- Names the sub-command `live` for upstream-parity.
- Points at **Xcode Previews** (`#Preview` macro, Canvas, interactive mode) as the native variant-cycling surface.
- Points at the existing `snapshot-previews/` convention docs.
- Explicitly scopes out the browser-style element picker. Mentions Xcode View Debugger as the closest inspection analog.
- Optionally references third-party **InjectionIII / Hot Reloading** as "if you want faster iteration" — not a dependency.

No runtime scripts ported. No `live-*.mjs` files in the Swift port.

### 2. Register — full parity

Port **both** `reference/brand.md` and `reference/product.md`. Brand register is valid on Apple platforms (marketing SwiftUI shells, portfolio apps, campaign surfaces). Router in SKILL.md selects register the same way upstream does: (1) cue in task, (2) surface in focus, (3) `register` field in PRODUCT.md.

Default inference for SwiftUI apps lacking a `register` field: infer once from PRODUCT.md's Users / Product Purpose sections, cache for session, nudge user to add explicit field via `/impeccable-swift teach`.

Shared design laws apply to both. Sub-command reference files add a `## Register` section only where the answer diverges — same posture as upstream.

### 3. Shortcuts — clean break

No `pin.mjs` shims for `critique` or `polish`. v0.2.0 collapses the three existing skills (`impeccable`, `critique`, `polish`) into a single `impeccable-swift` skill with sub-commands. CHANGELOG will call out the breaking change explicitly. User has confirmed they're effectively the only v0.1.0-poc consumer.

`pin.mjs` still gets ported as infrastructure (users of the Swift port may want to pin their own shortcuts), just not pre-applied for `critique` / `polish`.

### 4. Scope — full 3.0 port, no subset

All 23 sub-commands ported in one release. No "v0.2 critical-path + v0.3 rest" split. Sub-agents parallelize across commands, so throughput isn't the constraint.

### 5. Timing — everything on the upgrade branch

Phase 0 (this doc + UPSTREAM.md row) is the first commit on `claude/impeccable-3-0-upgrade-4MsLs`. No separate merge to `main` for Phase 0. Branch lands as one `v0.2.0` PR when Phases 2 + 3 are green.

### Phase 2 — implementation (parallel sub-agents)

**2a — Restructure (serial, blocker for 2b/2c).** Single sub-agent.
- Collapse `critique/` and `polish/` into the new skill tree.
- Rewrite `impeccable/SKILL.md` as the 3.0 dispatcher/router.
- Port `scripts/load-context.mjs`, `scripts/pin.mjs`, `scripts/command-metadata.json`. These are environment-neutral Node scripts; they port as-is modulo any file-path references.
- Skip: `live-*.mjs`, `live-browser.js`, `design-parser.mjs` (Node/CSS-specific), `modern-screenshot.umd.js`, `detect-csp.mjs`, `is-generated.mjs`, `cleanup-deprecated.mjs`.
- Keep our 4 Swift-native reference docs + accessibility in place under the new `reference/`.
- Keep `tools/`, `evals/`, `snapshot-previews/`, `transformers/` unchanged.

**2b — Reference doc ports (parallel).** One sub-agent per command (23 agents) or batched by class (3 batches: direct / blend / stub). Each agent:
- Reads upstream `reference/<command>.md` at `f5e82162`.
- Reads `docs/3.0-upgrade-plan.md` (this file) + `docs/3.0-command-inventory.md` row for its command.
- Produces `impeccable/reference/<command>.md` in the Swift port.
- Preserves Paul's voice and structure (declare → why → rule → anti-pattern).
- Layers SwiftUI examples and Apple-specific concerns per the inventory.
- Cross-links to our 4 Swift-native docs and accessibility where the inventory says to.

**2c — Merge updates to ported docs (parallel, independent of 2b).** Two small agents:
- Merge upstream's +45-line typography.md update into our ported `reference/typography.md`.
- Merge upstream's +70-line craft.md update into our ported `reference/craft.md`.

**2d — Router wire-up (serial, after 2a/2b).** Single sub-agent.
- SKILL.md frontmatter: version 0.2.0, expanded description covering all 23 commands, `argument-hint` per upstream pattern, `allowed-tools` list.
- Commands table in SKILL.md points at each `reference/<command>.md`.
- Setup section: `load-context.mjs` instructions, register selection logic.
- `command-metadata.json` filled out for all 23.

**2e — Detector wiring.** Single sub-agent.
- `audit.md` invokes SwiftLint custom_rules, `impeccable-lint` CLI, and asset-catalog-checker as the Swift arm of `npx impeccable detect`.
- `extract.md` optionally invokes `impeccable-lint` for pattern detection.

## Out of scope for v0.2.0

- Harness multiplication (`.agents/`, `.cursor/`, `.gemini/`, etc.). Upstream mirrors its skill tree into 11 harness directories. We ship via `npx skills add SeanSmithDesign/impeccable-swift` only; harness mirroring is a future concern.
- Browser Live Mode and its runtime dependencies.
- `design-parser.mjs` equivalent for Swift source. If `/document` ends up needing AST-level token extraction, impeccable-lint can be extended later — but the first pass does heuristic extraction from asset catalogs, color literals, and Font usages.
- `detect-csp.mjs`, `is-generated.mjs`, `cleanup-deprecated.mjs`, `modern-screenshot.umd.js`. These are web-specific or build-chain-specific.

## Risks

- **Voice drift across 23 sub-agent ports.** Mitigation: each sub-agent gets the same brief (this doc + inventory row); SKILL.md's "declare → why → rule → anti-pattern" structure is enforced in the inventory's definition of "direct" port.
- **Register choice regressing to product by reflex on Swift tasks.** Mitigation: brand.md ships with an explicit "Apple / SwiftUI doesn't mean product" callout; the one benchmark brief that exercises brand register is load-bearing in Phase 3.
- **Merge conflicts with our Swift-native additions.** Low — our 4 native docs and accessibility are in new files that don't exist upstream. The only overlapping files are the 8 ported reference docs, and 6 of those are textually unchanged upstream. Only typography.md and craft.md require a real merge.
- **Detector stack feels bolted-on in `audit.md`.** Mitigation: write the detector invocation as a clean "Swift detector arm" section that mirrors upstream's `npx impeccable detect` posture, not as an afterthought.
